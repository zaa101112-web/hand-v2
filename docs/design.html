Chrome 키 조합은 Chrome 공식 단축키 안내를 기준으로 합니다. 페이지 이동 키는 현재 웹 콘텐츠의 포커스나 페이지 자체 키 처리에 영향을 받을 수 있습니다. 자체 앱의 키 연결은 이 프로젝트가 정의한 규칙입니다.

단축키로 통일한다는 의미

Chrome에는 키 조합을 보내고, HAND 내부에서는 같은 의미 명령을 직접 호출합니다. 내부 기능까지 OS 키로 우회 실행하지 않습니다. 손의 위치를 마우스 위치·클릭·휠 값으로 변환하는 경로는 없습니다.

북마크 창은 HWND만으로 내부 대화상자 종료를 확실히 알 수 없습니다. G12 이후 confirmation_pending을 표시하고 일반 명령을 보류합니다. 사용자가 북마크 창을 닫은 뒤 작은 상태창의 계속을 눌러야 보류를 해제합니다. 이때 활성 상태는 유지하고 자세 해제를 다시 요구합니다. 임의 시간 경과나 V만으로 자동 해제하지 않습니다.

명령 승인 조건과 처리 순서

allow = RUNNING and ACTIVE and ready
        and not input_blocked_reasons and not release_pending
        and not dialog_lock and not confirmation_pending
        and event.context_version == current_context
        and now_ms - event.captured_at_ms <= 250
        and target_policy_allows(action)

우선순위: 종료/STOP/키 해제 → 오류 → UI 전환 → 확정된 일반 명령
일반 명령: 시효 + context + 중복 ID + 대상 창을 승인 시 / 실행 직전에 검사

앱 명령 대기열은 최대 8개이며 일반 명령의 유효 시간은 촬영 시각부터 250ms입니다. 넘친 일반 명령은 QUEUE_FULL로 차단하고 다시 실행하지 않습니다. STOP·해제는 별도 제어 경로로 항상 처리합니다. 프레임·후보·미리보기는 최신 1개만 유지하고 버려진 후보를 실행 명령으로 복구하지 않습니다. 처리한 event_id·command_id는 60초 보관합니다. 키 해제와 이미 시작된 캡처의 결과 정리는 오래된 context라도 소유 ID로 끝까지 처리합니다.

실제 키 조합은 짧은 down/up 한 묶음입니다. STOP보다 먼저 OS에 접수된 조합은 되돌릴 수 없으므로 완료 사실을 기록하고 이후 명령을 막습니다. ‘중단 요청’과 ‘해제 확인’을 분리하고 해제 완료 전에는 다시 시작하지 않습니다.

의존성과 실행 파일
